## Resolved: Foliate under the opaque sandbox -> separate reader origin (ADR-0071)

Finding: pristine Foliate reads each section iframe's `contentDocument`, which is null for children of an opaque-origin sandbox in Chromium, Firefox and WebKit (srcdoc rerouting also failed). The user chose a separate origin on 2026-11-14 and ADR-0071 records it (written by this worker at the user's direction although `ADR/**` is normally outside T005 scope — coordinator should review the ADR and the one-paragraph amendment note added to ADR-0067; `Validate-Adrs.ps1` passes for 71 ADRs).

Implemented: `webui.App` (app origin, never serves `/reader/`, exposes `/app-config.json` with the reader origin) and `webui.Reader` (serves only `dist/reader` at its root; no API/cookie/fallback routes; CSP with `sandbox allow-scripts allow-same-origin`, `default-src 'none'`, `connect-src blob:`, `frame-ancestors <app> <reader>` — the reader origin is listed because WebKit applies frame-ancestors to blob section frames). New config `LITARA_READER_ADDR`, `LITARA_PUBLIC_ORIGIN`, `LITARA_READER_ORIGIN` (required with `LITARA_WEB_DIR`; hostnames must differ, enforced by config tests); `cmd/server` runs a second listener. Frame URL carries `?parent=<app origin>` and the bridge only accepts a hello from `window.parent` with that exact origin; host posts to the exact reader origin. PDF.js now uses a normal same-origin module worker (the earlier fake-worker/blob workarounds were removed).

Test evidence (Playwright 1.65.1 bundled Chromium, Firefox, WebKit 27.2; app `127.0.0.1:8099`, reader `localhost:8098`; 27/27 pass): reader/app routing and CSP; EPUB text rendered by pristine Foliate; frame cannot read app cookie, app localStorage, parent DOM or fetch the app API; hostile EPUB script/`onerror` did not run, no script message, no completed external request; CBZ and FB2 open; PDF.js paints a 2-page PDF; entry ceiling rejects; forged/out-of-bounds bridge messages dropped; wrong-parent-origin hello ignored.

Not verified / limits: production reverse proxy + TLS with two real hostnames; Vite dev-server proxy does not serve the reader origin (dev needs `cmd/server` or `webserve`); MOBI, FB2 over 32 MiB, fixed-layout EPUB, CBR/CB7, malformed/encrypted/near-limit archives; selection/CFI/annotations; PDF cmaps/fonts/wasm not vendored; the ZIP ratio check applies only above 1 MiB expansion; browser versions are Playwright's bundled builds on Windows only; `PUBLIC_PATH_PREFIX` is not applied to web serving; `cmd/server` not run end to end with PostgreSQL.

## Milestone 2 (partial): server editions, titles and ebook file authorization

Governing ADRs: 0065 (editions), 0061/0045 (conservative linking), 0030 (init migration), 0058 (hash/versions).

Implemented and tested against real PostgreSQL 17.6 (Docker `postgres:17.6-alpine`) and ffprobe/ffmpeg:
- `editions` table folded into `migrations/00001_init.sql` (file ID unique; format/link_state checks). River migrations untouched.
- Scanner now catalogs `.fb2 .mobi .azw .azw3 .cbr .cb7` as well, never sends non-audio files to ffprobe, and `SyncEditions` gives each stable ebook/comic file exactly one edition. Titles come from bounded Go parsers (`internal/ebookmeta`: EPUB OPF incl. calibre/EPUB3 series and ISBN, ComicInfo.xml, FB2 title-info; PDF/MOBI/AZW fall back to the file name). Strong identifier + same normalized title/authors reuses a title; same text without an identifier creates a separate provisional title plus a `grouping` review item; filename-only titles are provisional. Existing editions are never touched, so identity follows the file ID across moves and same-path replacements.
- API (parity-checked against `contracts/t005`): `listTitles` (q literal substring, libraryId, mediaKind), `getTitle`, `listTitleRecordings`, `listEditions`, `getEdition`, `getReaderSnapshot`. Counts and children include only granted libraries; unknown 404; ungranted 403 `library_access_denied`; no fake recordings. Capabilities report only what is implemented/tested (epub/fb2/pdf/cbz read = supported; kepub/mobi/azw/azw3/cbr/cb7 = incomplete with reasons; resume/annotation capabilities = incomplete `not_implemented`).
- `getFileContent`/`headFileContent` now authorize ebook-only files through a granted edition (Range/HEAD/ETag/412 `content_changed` unchanged).
- `scripts/contracts/compare.py` merges the implemented T005 operations (`IMPLEMENTED_T005`) and reports every other T005 operation as PENDING (32 ops, 45 schemas); never remove contract routes to pass. Parity: OK. Normalization added: a zero minLength/minItems is treated as absent. `T005Problem` is documented in OpenAPI but the runtime body is still `Problem` until conflict routes add the extra fields.
- Tests: `internal/ebookmeta` unit tests; `TestEbookEditionsEndToEnd` (HTTP: editions/titles/reader, authorization both ways, original bytes + Range, same-path replacement keeps edition/file IDs and returns 412 for the old version); all prior server tests pass (`go test ./... -count=1`, sqlc diff clean, go vet clean).
