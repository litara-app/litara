## Not done, or only partly done

- **Manual merge / split of recordings** (ADR-0045): not implemented. Needs a tombstone for the merged-away recording that touches T003 catalog queries.
- **In-file metadata writers**: none registered; every format is disabled and the schema refuses enabling one without an evidence reference. The engine is exercised only by a test-only ffmpeg stream-copy writer. Per-format fidelity evidence (content, chapters, artwork) does not exist.
- **Provider adapters are unverified against the live services.** They were written against the documented response shapes and tested against local servers only. Audnexus's own README points new projects elsewhere; its current terms were not checked.
- **Real NAS behavior**: renamed-directory and unmounted-directory simulations only. No SMB/NFS, no Windows share, no atomic-replace evidence on a network filesystem. `os.Rename` replacement is atomic on local POSIX/NTFS; network filesystems are untested and the no-overwrite import publish falls back to a checked rename where hard links are unavailable (small race, documented in code).
- **Event hints**: no filesystem watcher exists; only scheduled and manual scans (the 15-minute reconciliation is the safety net the ADR requires, hints are not built).
- **Positions after replacement**: layout and version change are tested; the T003 412 behavior for an old saved position after a T004 replacement was not re-tested end to end.
- **Grouping by narrator/language inside one folder** is not split (see `contracts/t004/README.md`).
- **Concurrency of two servers** against one database is untested; scan serialization relies on the `scan_runs_one_active` index.
- **Ebooks**: cataloged as files only; no editions or reading entities.
- **Not run**: Android checks, hosted CI, any physical NAS / hardware, live provider calls.
- A filename-derived title (no tags) has no source row, so the metadata report can be empty for untagged media; the title column is still set.
- Inspector for scans is built without the legacy single `MEDIA_ROOT` restriction; containment is enforced by the scanner's canonical-root rules instead.

## Risks and notes

- `mustUUID` returns the nil UUID on a malformed value (existing T003 behavior); Huma's `format:"uuid"` rejects most bad values first.
- Huma requires path parameters as direct fields of the input struct (an embedded unexported struct silently does not bind).
- Admin routes validate the request body before the library-grant check, so an administrator without a grant who sends an invalid body sees 422, not 403. No data is exposed.
- Hash-based moves read whole files; a very large library's first scan is I/O heavy by design (ADR-0058).
- `contracts/t004/openapi.json` was generated from code, then compared; regenerate with the extraction approach in the history of this handoff if routes change.
