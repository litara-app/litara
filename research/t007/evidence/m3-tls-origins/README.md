# M3 evidence: local TLS with separate app and reader origins (2026-11-17)

Command: `python scripts/t007/tls_rehearsal.py` (results: `run.json`, 35/35 checks). The real server ran without `LITARA_DEV_INSECURE_HTTP`, with the built web app, a separate reader listener and distinct origins (`https://app.litara.test:18443`, `https://reader.litara.test:18443`), behind `scripts/t007/tlsproxy` (stdlib TLS terminator with a throwaway CA, host-based routing). Clients validate that CA and connect by IP with SNI.

Observed: validated handshakes for both hosts; no-CA and wrong-host-name handshakes refused; plain HTTP to the TLS port gets no HTTP answer. App origin serves the SPA with CSP, nosniff and frame denial, frame-src limited to the reader origin, `/reader/` not served. Reader origin denies `/`, `/api/*`, `/library`, `/admin`, `/auth/web/login`, carries a CSP and gives no CORS grant to a hostile origin. Web login cookies are all Secure with SameSite (session cookie HttpOnly); a cookie POST without a CSRF token, or from a hostile Origin, is refused; the API grants no CORS to any origin (same-origin only). Native bearer: login, authenticated original Range (206) and HEAD (size, Accept-Ranges), unauthenticated original refused, refresh rotation, session revocation stops both refresh and the access token. Hostile title/author markup is stored and returned as inert JSON text with nosniff.

Not covered: a real browser (CSP/sandbox enforcement, cookie behavior across the two origins, the reader iframe actually rendering), WebSocket/long-lived streams, replaced-file Range behavior over TLS, a production proxy (Caddy/nginx) configuration, HSTS, certificate rotation, packaging of the reader assets (separate open item).
