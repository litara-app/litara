# M4 evidence: credential log regression (2026-11-18)

`python scripts/t007/secret_logs.py` (results `run.json`): the real server at `LITARA_LOG_LEVEL=debug` was driven through good and bad password logins, bearer and malformed bearer use, refresh rotation, replay of a rotated token and a garbage token, web cookie and CSRF sessions, OPDS Basic (good and wrong), KOReader `x-auth-key` (good and wrong), integration credential creation, the SMTP password and its connection test, and a secret placed in a query string. 20 secret values (plus the login key and SMTP key ring key) were searched in the complete log in plain, URL-encoded, base64 and MD5 forms, and the log was searched for raw `Authorization`, `Cookie`, `Set-Cookie`, `x-auth-key` and `Bearer` markers: **no leak, no header dump**.

Honest limit: the log has only ~50 lines (startup, River worker debug, warnings) and **no request lines**; the server has no HTTP access log. So the result mostly shows that nothing logs credentials today, not that a redaction layer works; it also means failed-login attempts leave no log trail. The harness has a planted-secret control for its search forms but no leak was injected into the server. Not covered: the container's/proxy's own access logs, crash dumps, database statement logs, Android logcat (separate), the SMTP sink transcript.
