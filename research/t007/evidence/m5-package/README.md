# M5 evidence: unsigned local package and licence audit (2026-11-17)

## Package (G15, part of scenario `package-notices`)
Built from the repository root: `docker build -f deploy/Dockerfile -t litara-t007-package:test .` (linux/amd64, 177 MB, `image-contents.txt`). It contains the `server` and `ctl` binaries, the web app and reader assets built with `npm ci` from the lockfile (`/opt/litara/web`, 29 files, `index.html` and `reader/`), the pinned FFmpeg/ffprobe n8.1.3 LGPL static build (BtbN `autobuild-2026-11-12-15-40`, archive SHA-256 verified at build time, `BUILDINFO.txt` with source URL), and notices (`LICENSE`, server and web `THIRD_PARTY_NOTICES.md`, per-module license texts, FFmpeg `LICENSE.txt`). With the network disabled the container runs both tools; there is no host FFmpeg on its PATH. `bash scripts/t007/package_check.sh` runs the compose stack from the image: server ready, SPA with CSP, reader origin serving `frame.html` and no API, tools run inside the package (`package-check.txt`, 7/7). `bash scripts/backend/smoke.sh` passes (`backend-smoke.log`; one earlier run failed with a timing-sensitive fixed 2 s wait in `live_check_t004.py`, now a bounded retry loop).

Packaging defects found and fixed: the old image was backend-only (no web/reader assets); the compose file now builds from the repo root and enables `LITARA_WEB_DIR`, `LITARA_READER_ADDR` and two origins; the reader port default clashed with a host service, so smoke uses 18081. Finding: `npm ci` fails on Linux with the current lockfile under npm 11.21 (`@emnapi/core`/`runtime` missing) but passes with npm 11.6.2 as in `node:25.2.1`; the Dockerfile pins that Node version. Regenerating the lockfile is a decision for the web owner.

Not done: reproducibility (two builds were not compared; no checksum of the image is promised), Windows/macOS/arm64 packages, signing, an installable non-container package, and the Android APK/AAB artifacts (built by Gradle but not inspected for contents here).

## Licence audit
* **Server (Go).** 36 modules are compiled into `server`/`ctl` (`go-modules-licenses.json`: 14 MIT, 11 BSD-3-Clause, 6 MPL-2.0, 4 Apache-2.0, 1 BSD-2-Clause). Before this audit only 12 had notices or license texts; the other 24 (huma, pgx, River (MPL-2.0), goose, golang.org/x, tidwall, ...) now have license texts in `apps/server/third_party/licenses/` and rows in `apps/server/THIRD_PARTY_NOTICES.md`. License kinds were recognized from the texts by keyword; review before a release.
* **Web.** 32 production npm packages are bundled (`web-prod-licenses.json`: 30 MIT, 1 0BSD, 1 MIT OR CC0-1.0); `apps/web/THIRD_PARTY_NOTICES.md` is new and shipped in the image. `react-remove-scroll-bar` has no license file in its package (declared MIT).
* **Reader vendor.** foliate-js (MIT, pinned `78914aef`), zip.js, fflate, PDF.js 6.5.438 (Apache-2.0) with license files and checksums under `apps/web/public/reader/vendor/` (existing provenance).
* **FFmpeg.** LGPL static build, unmodified executables invoked as subprocesses; source reference and archive hash in `BUILDINFO.txt`. Not audited: the exact component licences inside the static build, and the offer-of-source wording for distribution.
* **Android.** AGPL application (ADR-0017). Dependency graphs: `android-deps-fullRelease.txt` contains `media3-cast` and `play-services-cast-framework`; `android-deps-fdroidRelease.txt` contains no Cast or play-services entries (0 matches). Android third-party notices were not re-audited.
