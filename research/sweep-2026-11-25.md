## 1. ADR inconsistencies

### High

**A1. ADR-0097 is accepted but contradicts ADR-0095's still-unamended text, and code still follows ADR-0095.**
ADR-0095 §1 defines `locked` as "user edit or inherited value frozen"; ADR-0097 §2 says only an explicit lock locks, and edits are merely "edited". ADR-0095 carries an "Amended by" header, which is fine, but the code has no separate lock state at all (see G1). The ADR set is consistent on paper only if a reader applies the amendment; anyone reading ADR-0095 §1–2 alone will implement the wrong model. Consider a one-line inline marker at ADR-0095 §1 and §2 as well as the header.

**A2. Two filter languages are accepted for the same concept.**
ADR-0066 smart shelves use a "bounded validated filter tree" (implemented as `T005Filter`/`T005FilterGroup`/`T005FilterNot`, `kind`/`children`). ADR-0085 adds a second tree for library search (`TitleFilter`, `type`/`join`/`rules`, BookOrbit-shaped) and defers "feeding smart shelves from a tree". Both are now frozen into the public v1 schema. Before the first API release, decide whether smart shelves move to the ADR-0085 tree (and the old one is waived), or record that the two will coexist permanently.

**A3. CBZ reader engine.** ADR-0027 assigns CBZ to Foliate; ADR-0067/0072 route ZIP/RAR/7z through one Go extraction path. The code follows 0072 (`ReaderPage.tsx:78` sends all comics to `ComicReader`). ADR-0027 was never amended, and the dead `cbz` Foliate kind remains (see C8).

### Medium

**A4. Page count and descriptive fields from providers.** ADR-0081 says "online providers stay a later opt-in" and leaves "whether providers should fill page counts" open. ADR-0090 (later, accepted) lets auto-fill "fill every field the match has". Close the ADR-0081 open question explicitly.

**A5. Amend-without-supersede is now the norm but the process doesn't describe it.** ADR-0071 (amends 0067), ADR-0096 and ADR-0097 (amend 0095), and the ADR-0069 note (0079 supersedes "the Mantine part") are partial amendments. `AGENTS.md` and `ADR/README.md` only describe full supersession plus a Superseded status. Add an "Amended by"/"Amends" convention to the template and validator, so partial changes are linked both ways. 0067 and 0069 currently carry back-links only as prose.

**A6. Stale open questions in early accepted ADRs.** ADR-0002, 0008, 0009, 0013, 0014, 0018–0022, 0024 and 0025 list questions later ADRs answered (0024, 0031–0043, 0047, 0082…), with no pointer. Some (0016, 0029, 0032+) do carry pointers. ADR-0095's open question "Cover size/type limits and where covers are stored" is answered by ADR-0086 but still listed as open.

**A7. ADR-0050 stability floor.** The ADR requires unchanged stat across observations "at least 30 seconds apart". The schema allows `stability_secs >= 1` (`migrations/00001_init.sql:267`). Either the ADR means a default (then say so), or the floor should be 30.

**A8. ADR-0038 page-size maximum isn't published.** The server rejects `size > 200` (`internal/httpapi/api.go:299`), but none of the 16 paginated operations declares `maximum: 200` in OpenAPI. Third-party clients can't discover the limit. Adding a maximum later counts as a narrowing (breaking) change under ADR-0082, so do it before the first release.

### Low

- **A9.** ADR-0069's Decision still reads "React/TypeScript/Mantine SPA"; only a note above it says otherwise.
- **A10.** ADR-0092's open question "Whether Android sends reading sessions" ignores that Android already sends sessions, but to a BookOrbit endpoint that doesn't exist (see G3).
- **A11.** ADR-0084 has two open questions (in-page find; keyboard focus past the drawn window) with no owner or test.

## 2. Code issues

Severity: **High** = wrong behavior or a security/data risk; **Medium** = a maintainability or contract risk; **Low** = cleanup.

### High

**C1. The Android app ships a second, BookOrbit-API client as its default path.** `core/network/ApiService.kt` declares about 70 Retrofit endpoints (`books/query`, `book-dock/*`, `collections`, `smart-scopes`, `dashboard/*`, `user-statistics/*`, `auth/oidc/*`, `audiobooks/{id}/playback-state`, …), none of which the Litara server serves. Twenty-five Android files use it: auth, browse, book detail, book dock, downloads, notes, audio progress/bookmarks, Android Auto catalog, reader progress/annotations/bookmarks, sessions and stats. `ServerSetupScreen`'s primary **Connect** button goes into this tree (`AuthenticatedApp`). The Litara path (`LitaraClient`, `feature/litara/*`) sits behind a secondary text button. Effects:
- A Litara user who taps the primary button gets a client that cannot work against this server.
- Android Auto (`AutoCatalog`, `AutoLibraryRepository`) uses `api.queryBooks`, so it is probably not wired to Litara. This needs checking against the T007 handoff, which treats Auto as deferred hardware.
- It contradicts ADR-0009 ("adapt Android networking and models to Litara") and ADR-0013 (OIDC deferred, yet the OIDC flow ships).

Needs a decision: delete the legacy tree, or keep it as an explicitly supported BookOrbit-compatibility mode (which would need its own ADR).

**C2. Recording metadata writes have no optimistic concurrency.** `PUT/DELETE /admin/recordings/{id}/metadata/{field}` take `SetMetadata {clear, value}` with no `baseRevision`/`operationId`. Edition writes take both (`T005MetadataWrite`). `MetadataTab.tsx:70–72, 86–89, 100` branches on this. A queued enrichment or a second administrator's edit can be silently overwritten on audiobooks. This violates ADR-0095 §4 and ADR-0047 commit-time protection. *Fixed 2026-11-25 (uncommitted): one revisioned `PATCH …/metadata` save for editions and recordings, with separate lock, unlock and reset actions.*

**C3. Auto-fill "Save" is N separate requests.** `saveDraft` (`MetadataTab.tsx:78–95`) writes each field in sequence. If it fails partway, some fields are saved and the rest are lost, with a revision chain the UI has to reconcile. ADR-0090 describes one Save. Add an additive batch write for the field set, under one revision. *Fixed 2026-11-25 (uncommitted): one revisioned `PATCH …/metadata` save for editions and recordings, with separate lock, unlock and reset actions.*

**C4. "Unlock" deletes the value.** `unlock` calls `DELETE …/metadata/{field}`, and the server deletes the user-source value (`reading/editionadmin.go:332–352`). Under ADR-0097 §3, unlock must keep the value, and "Reset to source" is a separate action. Today they are the same operation, and the UI labels every user value "Locked" (`MetadataTab.tsx:11`). *Fixed 2026-11-25 (uncommitted): one revisioned `PATCH …/metadata` save for editions and recordings, with separate lock, unlock and reset actions.*

### Medium

**C5. 113 of 186 public schema names carry internal task IDs** (`T005Edition`, `T005Annotation`, `T009Titles`, …), and there are about 950 `T00x` identifiers in non-generated Go. These leak project-management history into the public v1 contract and into any generated client. The ledger has no released version yet (`snapshots/ledger.json` → `releases: []`), so renaming now is cheap. After the first tagged release, the names are permanent under ADR-0082.

**C6. Web API types are hand-written.** `api/types.ts`, `api/t006.ts` and about 110 inline interfaces aren't generated from or checked against the OpenAPI document. ADR-0082 guards the server side only, so web/server drift (for example a renamed response field) is caught only by Playwright, if at all. Generating types from `baseline.openapi.json` (for example with openapi-typescript) is routine tooling under ADR-0069.

**C7. Media-split APIs for one concept.** Title completion history is split into `GET /titles/{id}/history` (recordings, T003) and `GET /titles/{id}/reading-history` (ebooks, T005). The web only calls the latter, so audiobook completion history never appears in the Reading log (ADR-0022: completions roll into the title's history). The same split exists for completion-conflict resolution (C10).

**C8. Dead or stale reader code.**
- `ReaderKind "cbz"` and `KINDS.cbz` (`ReaderPage.tsx:22`, `host.ts:8`) are unreachable, because line 78 sends every comic to `ComicReader`.
- `ComicReader.tsx:75` still says "CBR/CB7 extraction is not available yet", which is untrue since ADR-0072.
- Annotation `color`/`style` plumbing (`host.ts:39–42`, `public/reader/bridge.js:222`) is never set by any caller and belongs to **Proposed** ADR-0094. Either finish the ADR or remove it, so unapproved behavior isn't half-built.

**C9. Reading-session upsert can silently drop data.** `UpsertReadingSession` is `:exec` with `WHERE reading_sessions.edition_id = EXCLUDED.edition_id` (`db/queries/sessions.sql:11`). A reused session ID for a different edition updates nothing and still returns success. Return the row count and reply 409.

**C10. No web UI to resolve audio completion conflicts.** `PendingPage.tsx:59` explicitly hides resolve buttons for `recording-completion`, and `POST /recordings/{id}/completion-conflicts/{conflictId}/resolve` has no web caller. A web user can only discard the change. ADR-0034/0035 call for an explicit choice. *Fixed 2026-11-25: Pending changes shows both states and offers Keep what is saved / Use my change, resolved against the current revision.*

**C11. No device-session management UI.** `GET /sessions` and `DELETE /sessions/{id}` have no web or Litara-Android caller. ADR-0033 says "devices can be revoked individually", which today is only possible through the raw API.

### Low

- **C12.** Unused sqlc queries: `DeleteTitleCover`, `GetConfigByID`, `MarkInspectionCancelled`, `SetFileAvailability`, `UpsertRootHealth`. `GetScanRun` and `ListAssociations` are used only in tests. Unused Go: `accounts.DecodeTokenPair`. Unused web UI primitives: `Divider`, `Grid`, `Section` (`ui/layout.tsx`), `Pager` (`ui/nav.tsx`).
- **C13.** `apps/server/internal/store/` is an empty, untracked local directory.
- **C14.** `GET /me` has no client; the web uses `/auth/web/session`. Fine for third parties, but nothing exercises it outside tests.
- **C15.** `main.tsx` imports the full variable-axis Fraunces CSS (`full.css`, `full-italic.css`) globally. Check the bundle cost against the axes actually used.
- **C16.** The cover fetcher's `publicIP` (`covers/fetch.go:80`) doesn't refuse `0.0.0.0/8`, NAT64 (`64:ff9b::/96`) or 6to4 (`2002::/16`), which can map onto private IPv4. It already resolves at dial time and pins the IP, so the residual risk is small.
- **C17.** 178 integration tests skip silently without a database. `LITARA_REQUIRE_INTEGRATION=1` exists. Make it the documented default for pre-merge runs, or add a compose service, so "tests pass" can't mean "most were skipped".

### What looks good

Layering (httpapi → service packages → sqlc) is consistent, and Huma registration is uniform. The SSRF guard, archive bounding (ADR-0067/0072), idempotent receipts and the apicompat checker are carefully done. No unnecessary abstraction layers stood out on the server; the larger simplification wins are the duplicated filter languages (A2), the media-split history/conflict endpoints (C7/C10) and the legacy Android client (C1). Every API operation has a caller somewhere, except `/sessions`, `DELETE /sessions/{id}`, `/titles/{id}/history` and `/me` (and the recording completion-conflict endpoint, which only Android calls). Artwork, file content and comic page images are reached through server-supplied paths (`coverPath`, `contentPath`), not hard-coded URLs, which is good.

## 4. BookOrbit features vs Litara

Source: the BookOrbit README and the docs landing page at bookorbit.app (pages listed only in the docs sidebar weren't read). BookOrbit is NestJS + Vue + PostgreSQL, AGPL-3.0 with additional terms, so ideas only, no code reuse into MIT web/server (ADR-0017). It supports local filesystems only, while Litara supports NAS mounts (ADR-0050), which is a differentiator worth keeping.

**Already at or near parity:** multi-library with per-library modes; grid and virtualized table; AND/OR filter builder; manual, shared and smart shelves; web readers for the same format matrix; web audio; Android with Cast/Auto; OPDS 1.2 + 2.0; send-to-email; KOReader progress sync; Open Library, Google Books, Audnexus and Hardcover metadata; per-field protection; cover search and replacement; reviewed in-file write-back (more careful than BookOrbit); per-library access, private annotations and progress; reading-session capture.
