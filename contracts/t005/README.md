# T005 implementation contract

Status: assignment contract under accepted ADR-0065–0070, approved 2026-11-14. **No T005 application routes are implemented by this preparation.**

- `openapi.json`: 38 additive operations and 65 schemas. Paths are relative to `/api/v1`. Existing T003/T004 routes and auth names remain authoritative and unchanged.
- `model.md`: persistence, semantics and transaction/permission boundary, including constraints JSON Schema cannot enforce.
- `examples.json`: positive/negative wire examples.
- `identity-fixtures.json`: public synthetic IDs, not credentials or content hashes.
- `scenarios.json`: 38 required acceptance scenarios, not a report of completed tests.
- `../../handoffs/T005-assignment.md`: exclusive ownership, milestones and evidence required.

Run `python scripts/contracts/check_t005.py` for static preparation validation. Install the existing pinned contract dependencies into `.tmp/t003-validation` using `scripts/contracts/requirements.txt`. This checker does not run Go or build application artifacts. Keep the existing application parity check on T003/T004 until implementation adds T005; the T005 worker must extend that checker to merge this additive contract and require parity before handoff. Never regenerate a contract from code to hide drift or drop routes to make parity pass.

## Transport and authorization

Keep ADR-0038 conventions: UUID resource IDs, string revisions, zero-based page/size (50 default/200 maximum), typed problem errors. Page results are sorted deterministically by resource ID unless explicit manual-shelf order or completion-history receive sequence applies. Text search `q` uses case-insensitive Unicode-normalized literal substring matching against visible title/author/series fields; it is not SQL or a regular expression. Totals/counts and title children include only the caller's granted libraries. No inaccessible IDs, names, state counts or content paths are returned through lists, shelf filters, repair warnings or hints.

Browser writes use the existing protected session cookie and CSRF scheme; native clients keep bearer transport. Cookie and CSRF names come from T003. Caller/user/owner IDs are never accepted as write-body authority. Administrator status does not bypass a library grant or confer access to private annotations, personal conflicts or private shelves. Shared shelves are readable by signed-in viewers, editable only by their owner; catalog management still requires administrator AND grant. Private object access by a different user returns 404. Library access checks retain T003's documented error order for media; unknown objects and denied objects expose no payload.

## Editions and reading

Each distinct supported ebook/comic file initially owns one edition. Scans create editions for stable files, including incomplete/unsupported capability states where parsing fails. Title linking uses ADR-0061's strong-identifier/metadata agreement; uncertain links are provisional review items. One edition/file identity survives recognized moves and same-path content replacement; replacement changes the version and invalidates incompatible locations. `PUT /admin/editions/{id}/title` links to a title represented in the same granted library; `titleId:null` separates the edition into a newly created title. It is revisioned/idempotent and never changes files or personal state. Metadata for display uses protected edit > sidecar > embedded > provider-gap precedence, with T004's protected clears retained. Do not invent new in-file ebook writers.

Under ADR-0078, confirmed EPUB or KEPUB container damage reports `readiness: incomplete` with issue code `file_damaged`. The issue is scoped to the current file version. The original remains available to authorized clients, and replacing the bytes leaves the edition and its personal history intact.

The existing `/files/{id}/versions/{version}/content` GET/HEAD/Range endpoint must authorize ebook editions as well as recordings. No fake recording should be created to serve an ebook. Preserve original bytes, size/ETag/Range semantics, grants and replacement errors; add actual integration coverage for ebook-only libraries and T004 replacements. Reader snapshots carry capability states; do not return executable application credentials in them. Unsupported/missing books remain visible but do not claim reading support.

Edition metadata endpoints expose effective values, provenance, protected clears and suppressed evidence. They compare the edition revision and use operation receipts; success returns the new report revision. Field types: title/series_name/language are strings, authors/tags are string arrays, series_index is a nonnegative number. `clear:true` requires `value:null` and protects the empty field; otherwise value must have the field's type. DELETE removes the protected override so lower-priority sources may apply; it is distinct from a protected clear. Bounded Go-based metadata parsing may extend scanner inspection for ebook formats; failed/unsupported extraction retains filename fallback with explicit evidence/issues. Do not require FFmpeg to parse ebook text, silently merge translations, or copy AGPL parser code. User-edited metadata does not change media bytes. Source `filename` is explicitly the lowest fallback, not fabricated embedded metadata. Existing opt-in provider settings and confidence/review rules remain in force; provider failures must remain visible and no live verification is claimed by fixtures.

Typed locator version 1 supports Foliate CFIs, PDF page/coordinates and comic page identities. Foliate locators are interpreted only by a pinned compatible renderer profile recorded in the snapshot; test real renderer-generated CFI/ranges for each supported format. Server validation checks size, syntax, edition/file/version, locator kind/profile and known bounds; it cannot prove every textual CFI resolves. The renderer must reject unresolved CFIs visibly rather than substitute a percentage. PDF coordinates are fractions of the unrotated crop box measured from its top-left; x/y and rectangle extents must be within [0,1], with positive dimensions. Convert to/from PDF.js viewport coordinates explicitly, including crop offset/rotation. A comic entry ID is SHA-256 of normalized relative archive path UTF-8 (not a public file identity); page index, entry ID and manifest version must all agree with the exact file/version. All page indices are zero-based.

`engineProfile` is a versioned compatibility profile, not just an arbitrary package version. A worker pins tested engine revisions and records which profiles they can produce/consume. A changed engine must not silently reinterpret an existing locator. Exact-file locators never automatically migrate across bytes/formats; the future legacy importer is separate work.

Position and completion start at revision `"0"`. Position is nullable; finish/unfinish is manual and updates only that edition plus immutable ebook title history. Existing T003 recording history remains unchanged; `/titles/{id}/reading-history` adds ebook history separately and the UI combines the two without reinterpreting old recording records. Completion does not clear or move a precise location.

## Personal mutations, retries and conflicts

Receipts are unique per authenticated user + operation UUID across all T005 personal mutation kinds, including HTTP method/resource identity in the canonical request fingerprint. Write state/revision, receipt, conflict or history atomically with row locks/compare-and-swap. Identical retries return the original status/body; reuse with different semantics returns 409 `operation_id_reused`. A request failing 401/403 must not create a receipt for another account. Validate malformed bodies as 422 before creating a candidate.

Wrong base revision returns 409 `stale_revision` with durable candidate/conflict ID and current revision. Changed content or incompatible locator profile returns 412 `content_changed`/`locator_incompatible` with durable candidate. Successful explicit backward navigation is valid. Do not use device clocks or highest percentage to choose state. Keep receipts/conflicts/tombstones indefinitely in this scope. A conflict belongs to the original caller; `resourceKind` disambiguates state and `resourceId` names edition, annotation or shelf. Membership candidates include normalized action/title ID even though the route body need not repeat them.

`GET /personal-conflicts` returns only the caller's conflicts under current resource permissions. `POST .../resolve` uses a new operation ID and the current resource revision. `keep_server` resolves the candidate without replacing resource state; `use_candidate` reapplies the retained candidate only after revalidating current file/access/record state. It must not resurrect tombstones. On a resolution race, create another durable 409/412 candidate without destroying the original. `T005Resolved.revision` is the resulting resource revision; keep-server leaves it unchanged. Resolved conflict IDs remain retained and an identical resolution retry replays its receipt. Requests to an already resolved conflict with a different operation return 409 `conflict_resolved`.

The web app stores pending writes in server/user-scoped IndexedDB before sending, with original operation IDs/base revisions/content versions. Authentication failure pauses sends without discarding notes. Logout/account switch closes renderer/audio, clears protected visible state, locks pending data and never assigns it to the next account. A subsequent valid same-account login unlocks and reconciles it. Detected grant removal blocks the affected queued data/content. This is retry recovery for online use, not offline book downloads; no service worker is selected.

## Annotations and shelves

Annotations are private. The path annotation UUID is client-generated to make creation replayable; base revision 0 creates only if the UUID has never existed. Kind is immutable. A highlight requires a same-kind valid selection/range and a text-selection capability; a page bookmark/note has `selection:null`. A note requires nonempty text; a bookmark may have empty text. Image comics cannot create text highlights. Highlight quote/text are untrusted display data. Annotations are editable only against their anchored current version; superseded annotations remain recoverable, visibly detached, and never painted onto changed content. A deletion is permitted with the correct annotation revision even when its book bytes are superseded, because deleting personal state does not reinterpret a locator.

Delete retains a tombstone with ID/revision/deleted=true/data=null. Retain conflicting edit content in private evidence; a stale edit cannot recreate the ID, and explicit restore is not included. Owner list defaults include tombstones so retries can reconcile. Normal UI hides them. `includeDeleted=false` is only a view filter, not permission to prune. Lists are a live paginated view, not a snapshot/delta-sync guarantee: reconcile before writes and preserve 409s; do not implement “missing from a page means deleted.”

Shelf creation also uses a client UUID/base 0. `kind` is immutable; visibility/name/filter changes require current shelf revision. Deleted shelves retain owner-only tombstones, while other callers receive 404. OwnerId/canEdit/counts are server-derived. Manual shelf data requires `filter:null`; smart data requires a filter and rejects membership/order mutation. A manual membership is unique by shelf/title; additions append and removals preserve other order. Each mutation increments the shelf revision atomically, including membership/order. Owner must have current access to a title when adding it. Losing access hides a member without silently deleting it. Removing a now-inaccessible member is not exposed through its hidden ID.

`orderShelfTitles.visibleTitleIds` must be a complete permutation of the owner's currently visible members at the expected revision. Reorder visible slots only; keep hidden members in their relative slots. Never return hidden UUIDs to make a client submit the order. A concurrent grant/membership change fails with 409 and requires refetch.

Smart filters allow `all`/`any`/`not` nodes and predicates, at most depth 4 and 32 total predicates; serialized filter at most 32 KiB. String values are normalized NFC + Unicode case-folded; `contains` is a literal substring and `equals` matches a complete field value. Multiple public field values match if any does. `finished`/`inProgress` require equals with string `true` or `false`; `format` requires one accepted lowercase extension, `mediaKind` equals `ebook` or `audio`. Boolean/mediaKind/format reject contains. Finished means any currently permitted child edition/recording has current completion=true; inProgress means any permitted unfinished child has a saved exact-file position. Count only permitted children. Language/tag/series/author predicates operate on visible public catalog values; absent fields do not match. Shared smart shelves evaluate grants/state of the current viewer, never the owner. Sort derived results by title UUID; no manually persisted smart membership or private annotation predicates.

## Comics and reader isolation

ADR-0067 governs isolation and all resource ceilings. `POST .../pages` is an authorized user-triggered durable extraction request, not catalog management; deduplicate by file/version/profile and reject a mismatched body contentVersion. Return 202 manifest state even if already ready; identical operation replay is stable. GET manifest is read-only and does not start a job. GET/HEAD page serve exact-version validated images only, check grants again and return private/no-store cache headers. Image page responses include fixed MIME, Content-Length and ETag; HEAD has no body. Stale file versions return 412, a pending manifest returns 409 `pages_not_ready`, unsupported limits return typed 409 `archive_limit`/`unsupported_archive`. Original-file Range support remains on the existing file-content endpoint.

Cache keys include file/version/extraction profile; entry identity/order is deterministic and cannot be user-supplied filesystem paths. Manifests are not published ready until bounded validation succeeds. Never place extracted book paths or cache locators in public responses. Foliate CBZ stays the selected engine; apply preflight/streaming limits to its ZIP extraction too. Go CBR/CB7 libraries and image decoders require verified licenses/pins and explicit unsupported states for unhandled variants. No unapproved native executable or format conversion is selected.

The opaque sandbox receives no cookie/token/CSRF values and cannot fetch arbitrary URLs. Its bootstrap channel must be bound to the source frame, active book/version and generation, with message schemas, byte budgets and cancellation. The app performs all authorized fetches and user-approved mutations; no generic API proxy. Logs/errors must not leak book text, notes or credentials. The worker must prove engines/modules/workers and browser-side decompression limits under actual production headers before claiming reader completion.

## Reviewed recording repair

ADR-0070 is authoritative. A merge plan has >=2 sources/one output; split has one source/>=2 outputs. All sources must be active, same title/library, with distinct current file sets. Outputs are an exact one-to-one partition of all source file/version memberships in explicit order; output keys are unique. No dropped/duplicated/cross-version files. Title linking is not hidden inside repair.

Plan/approve/apply/cancel require admin+grant and operation receipts. Plan create uses operation UUID for replay. Subsequent actions compare plan revision; execution rechecks every source layout/version and locks sources in UUID order. Approval does not waive later revalidation. Atomic execution creates successor recordings and tombstones sources, returning key-to-new-ID results; execute replay returns identical IDs. Cancel is allowed before apply only. Keep filenames/bytes/file IDs untouched and rederive chapters/readiness from valid source evidence.

No source personal state is overwritten or exposed in administrator warnings. Old snapshot 409 and old mutation 412 use existing typed errors with additive `successorRecordingIds` only for granted callers; update the T003 contract/fixtures for these documented repair error responses without changing successful unrepaired snapshots. Source history and the caller's source state remain readable under grants. New successors start unfinished/no canonical position; expose valid source file/version positions as explicit candidates via the existing recording-position conflict model (new source-recording context is additive). Do not fabricate a candidate operation as a write from another user. Subsequent explicit user resolution produces normal revisioned state. No source-completion event is automatically applied to a successor.

## Preparation versus implementation

Static validation checks schema/examples, scenario references, unique routes/schema names and transport/permission declarations. It cannot prove real parsing, isolation, conflict transactions or browser playback. Completion requires the scenario matrix, real local tests and an evidence-backed handoff, with broad format failures and untested hardware stated explicitly. No CI reactivation, publication or migration conversion is authorized here.
