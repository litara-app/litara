# T003 shared API contract

Status: implementation contract for the accepted T003 slice; no claim these endpoints exist yet. Version: 0.1.0-development. Governing ADRs: 0009, 0013, 0018–0022, 0024, 0029–0043. The accepted policies prevail over accidental schema omissions; report a conflict rather than inventing a new policy.

- [OpenAPI 3.1](openapi.json) defines methods, paths, security, request/response bodies and reusable schemas. All paths are relative to the configured /api/v1 base.
- [Model and ownership](model.md) defines the minimal seeded persistence boundary.
- [Examples](fixtures/examples.json) include valid and deliberately invalid JSON instances.
- [Version examples](fixtures/recording-versions.json) cover ordering, replacement and an unchanged old download.
- [Range cases](fixtures/ranges.json) are normative byte-response examples, including offsets above 4 GiB.
- [Chapter source cases](fixtures/chapter-sources.json), [authorization matrix](fixtures/authorization.json) and [refresh exchanges](fixtures/auth-exchanges.json) fix validation, grant and timing edge cases.
- [Behavior cases](fixtures/scenarios.json) are required runtime test scenarios, not executed application tests.

Run the contract checks from the repository root:

~~~powershell
python -m pip install --target .tmp/t003-validation -r scripts/contracts/requirements.txt
python scripts/contracts/check.py
pwsh -NoProfile -File scripts/Validate-Adrs.ps1
~~~

The validator checks OpenAPI syntax/references, every component schema, positive/negative examples, recording-version arithmetic, range expectations and scenario inventory. It does not execute authentication, media, database or Android behavior. T003 must convert the scenarios into real integration tests and compare Huma's generated OpenAPI semantically with this contract. Do not maintain divergent handwritten DTO schemas.

## Wire rules

JSON uses camelCase; every displayed required property is present, including explicit null when unknown/absent. UUIDs are opaque strings; never parse paths, ordering or authorization from them. Revision values are decimal strings to avoid JavaScript precision loss; initial user/recording state is revision "0". Layout and content versions are distinct UUIDs. Durations, offsets, sizes and sequence values are nonnegative integers representable exactly by JSON clients (up to 2^53-1); durations must be positive when known. Timestamps are RFC 3339 UTC. capturedAt is display context, never the ordering authority.

Use RFC 9457 application/problem+json errors with stable code, type, status, detail and requestId. Clients branch on code/status, not detail text. Do not echo submitted credentials, raw paths or complete request bodies in errors, logs, examples or validation errors. The operation response lists describe possible classes, not a requirement for every operation to return every class.

| Status | Meaning / sample code |
| --- | --- |
| 400 | Malformed JSON/range: malformed_request |
| 401 | Missing/expired access, invalid credentials, revoked/expired session; token_expired, session_revoked, refresh_reuse, refresh_retry_expired |
| 403 | Authenticated but no grant/admin authority; library_access_denied, admin_required, csrf_failed |
| 404 | Unknown recording/file/version/artwork/session in the caller's permitted scope; not_found |
| 409 | position_conflict, completion_conflict (durable conflictId), operation_id_reused, recording_incomplete |
| 412 | layout_changed, content_changed; preserve candidate, return currentLayoutRevision and conflictId for sync writes |
| 416 | Unsatisfiable media range, Content-Range: bytes */size |
| 422 | Invalid fields/offsets: invalid_position, validation_failed; never silently clamp |
| 429 | Request throttled: rate_limited; include Retry-After |
| 503 | Temporary storage/database/media unavailability: temporarily_unavailable; never delete catalog state |

For an existing unauthorized library resource, return 403 without disclosing its metadata. Check authorization before returning content validators, conflict/receipt data or existence details. Truly unknown IDs return 404. Responses containing credentials/CSRF or private metadata use Cache-Control: no-store (media/artwork: private, no-store). Requests mixing cookie and bearer credentials are rejected with 400 ambiguous_credentials. Huma validation failures must use this safe typed error shape.

## Discovery and compatibility

GET /discovery is public and returns stable serverId (persisted once), apiVersions, apiBasePath, development stability and capabilities. It reveals no accounts, library names or media. Preserve serverId across normal restarts and URL changes; record it in backups. Copying/instantiating a distinct independent server requires a new identity through an explicit operator operation, not an incidental URL hash. Clients key local ownership by serverId + userId, verify the server before resuming a scope and never treat a matching UUID as a substitute for TLS trust.

Support a configured reverse-proxy mount prefix: returned content/artwork paths are server-relative under that prefix, not filesystem paths, external redirects or expiring credentials. Do not forward bearer credentials to another origin. OpenAPI servers defaults to /api/v1; deployment configuration supplies the actual public prefix. Expose generated API docs/spec at the configured API base and retain T001 health/readiness outside the public data contract.

All collections use page=0 and size=50 by default; size caps at 200 and response echoes its effective value. Invalid negative/noninteger/zero sizes -> 422; size above 200 is capped. Return total after authorization/search/filtering, not global counts. Page beyond end -> empty items with total unchanged. Stable ordering is title then ID, or server lastActivityAt descending then ID for sort=recent. completion=unfinished supports Continue Listening; filter active user/library grants before counting. Search q covers title, authors and narrators for this audio slice; deterministic case-insensitive matching is sufficient (accent-insensitive ranking is not a requirement). Results are not frozen snapshots during catalog mutation.

The API is explicitly unstable before production. Contract changes require updated examples and ADR compatibility review; do not advertise production compatibility yet. At production freeze v1 becomes backward compatible; deprecation/support windows belong to release policy.

## Accounts, grants and authentication

Local operator CLI initializes first admin without a public setup route or a default password. First-admin creation is atomic and refuses an already-initialized server. Read passwords from an interactive prompt or protected stdin, not process arguments, logs or committed env files. Admin HTTP operations create users, toggle active/admin status, and add/remove explicit grants. Prevent removing/deactivating the last administrator. Creation has no implicit library grant; admins may explicitly grant themselves access. Password recovery UI/email, self-registration and OIDC are not part of this slice. Provide a local operator password-reset command that revokes that user's sessions; do not invent a remote password-recovery protocol.

GET /me and /sessions expose only the current account; DELETE /sessions/{id} revokes only its own device session (otherwise 404). Normalize usernames by Unicode NFC, trimming surrounding whitespace and Unicode lowercase for lookup/uniqueness; retain the trimmed display spelling. Never normalize passwords. Native login returns opaque access/refresh credentials, session deadlines and stable user identity. Access expires in 900 seconds; idle refresh expiry is 30 days and absolute session expiry 90 days. Successful authenticated requests and fresh refresh exchanges renew idle use without moving the absolute deadline. Do not renew deadlines for denied/expired requests or idempotent refresh retries. Every new authenticated request checks active account, session and current library grant. Native logout revokes the current session even if other sessions remain.

Use secure random opaque tokens and credential verifiers in ordinary DB rows; never store reusable plaintext tokens in logs. Password hashing must use a reviewed password-specific KDF with configurable work factors; select the concrete package/parameters from current primary documentation during implementation and review them as security implementation details. This contract does not authorize adding OAuth password-grant compatibility or weakening local login.

Refresh is a transaction keyed by session, presented refresh-token generation and requestId. First use rotates once, stores the old-token/requestId association and a protected recoverable successful response for 60 seconds. Within that window, the identical exchange returns identical status/body/credentials/deadlines; it never rotates again. Old-token use with a different ID revokes this device session, including its current access credentials; it does not revoke other devices. The same old token/requestId after 60 seconds -> 401 refresh_retry_expired, no new tokens (do not classify that known retry as different-ID reuse). Retain a nonsecret digest/tombstone sufficient to distinguish it; delete protected response credentials after 60 seconds. Concurrent exchange/reuse must be atomic and may not return credentials from a revoked session. Return 401 with a stable code on expiration/revocation; transient 503/network failures preserve the client scope. After an ambiguous refresh failure, persist/retry the original requestId rather than issuing a second exchange. Client refresh is single-flight per session.

Browser login sets litara_session with HttpOnly, Secure, SameSite=Lax, Path={mount}/api/v1 and no Domain; it returns BrowserSession, not bearer credentials. The cookie is server-backed with 30-day idle/90-day maximum. GET /auth/web/session returns current session and a session-bound CSRF token. Check an allowed same-origin Origin on browser login and all cookie-authenticated state changes, plus X-CSRF-Token on authenticated changes. Login does not need a preexisting session token; reject cross-origin login. Native bearer operations do not require browser CSRF headers. Browser logout clears the cookie with identical scope and revokes that session. CORS is same-origin for credentialed browsers; third-party native API clients remain allowed.

Production requires HTTPS, including trusted proxy termination. Explicit development-only HTTP configuration is allowed for local/emulator/LAN fixtures and must be opt-in at client and server; it never follows a TLS failure automatically. In that mode only, document the non-Secure development cookie exception and show that transport is insecure. Use synthetic test accounts. Normal deployment must not silently relax cookie attributes.

## Recording snapshots, readiness and chapters

GET /recordings/{id} is the self-contained schemaVersion=1 offline snapshot, not a separate incompatible playback manifest. It contains title/library/recording IDs, display metadata, completion summary, layoutRevision, ordered files (IDs/content versions/sizes/MIME/durations), chapter file/version anchors and derived recording starts, artwork paths, issues and capabilities. Progress is retrieved separately, stored alongside the snapshot under the same account scope. Do not store local paths as API identities. A recording has at least one file, sequence is contiguous from zero, file IDs occur once, and totals are derived from known positive durations. Unknown numeric data is null, never fabricated zero. Actual generated media sizes must come from inspection/stat, not the abstract JSON fixture sizes.

A ready recording requires every file present/readable, supported for this slice and with known positive duration/size. Otherwise publish explicit incomplete with play/download/wholeRecordingSeek=false and issues. Authenticated content access associated with an incomplete current recording returns 409 recording_incomplete; missing/offline storage transiently returns 503 rather than deleting the resource. Chapterless recordings can be ready. Do not transcode, rewrite containers or extract artwork by modifying originals. Seed artwork from a generated provenance-known image; absent artwork paths are null and endpoints return 404.

Select one valid chapter source: protected explicit user edits, valid associated CUE, embedded, then generated file-boundary markers. Validate source starts as a whole in recording order: any negative, duplicate, descending or out-of-file offset rejects the source and emits an issue; a later file restarting at offset zero is not by itself descending. Valid starts satisfy 0 <= offset < known file duration and matching file/version identity. Preserve rejected raw sources and explicit edits for repair. Unknown timing makes the recording incomplete. Do not merge sources or silently sort/salvage a broken source. CUE association/parsing is T004; T003 uses seeded normalized candidate sources to prove selection and validation. Chapter ends are not published in this slice; a chapter may span files up to the next start. Do not invent authored chapters for intro gaps. Generated file markers use source=generated and generated=true, starting at each file boundary. Whole-recording starts equal known preceding durations + local offset. Layout revision changes on membership/order/content/duration/effective chapter changes affecting the playable snapshot.

Keep a complete old download bound to its old snapshot/content versions when bytes change; show update available and require explicit redownload. A new version is staged separately and published locally only when its complete snapshot/download validates. Do not silently replace bytes or offsets. Online access revocation still locks the old snapshot. Server retention/serving of superseded bytes is not promised: 412 content_changed for a formerly known version no longer available, 404 for an unknown version; the old authorized offline copy can remain playable. T004 owns move/content matching and lifecycle detection.

## Position, conflict and completion transactions

GET /position always returns PositionState; no position is {revision:"0",position:null,unresolvedConflicts:[]}. GET /completion starts at {revision:"0",finished:false,changedAt:null}. Position and completion revisions are separate per user/recording; do not reuse layout or content revisions for them. Preserve per-device captured context while a canonical accepted position has a server-issued revision. Device clocks do not order writes.

For a fresh write: authenticate/authorize; validate operation ID ownership/payload, recording/file/content/layout, then base revision and offset. Store receipt, state update or conflict candidate atomically. A successful write increments the server revision, including intentional backward movement. Repeating an identical recorded operation returns its original status/body only when still authorized, without revalidating it as a new write. Same ID with different normalized payload -> 409 operation_id_reused. Idempotency scope is user + recording + operationId across progress/completion/resolution commands; the operation kind is part of the fingerprint. Preserve receipts without automatic pruning; refresh credentials are the separate bounded exception.

Stale position -> 409 position_conflict with durable conflictId and current PositionState. Changed layout/content -> 412 layout_changed/content_changed with durable candidate, conflictId and currentLayoutRevision; it does not silently remap. A valid file/version anchor after reorder can be resubmitted with a new operation ID/current layout after client validation, but not if content changed. Valid position offset is 0 <= offset <= known duration (the final endpoint is a resume position, distinct from chapter starts); do not clamp. Unknown/nonmember/mismatched anchors are rejected, not interpreted as another file.

Ask which competing position to use on resume. POST /conflicts/{id}/resolve supplies a new operationId, current baseRevision and layoutRevision. keep_server requires position=null; use_candidate requires position=null and revalidates the saved anchor; use_explicit requires a supplied valid new anchor. Success atomically marks that conflict resolved and returns the new current state; it does not delete raw evidence. Any state advance while choosing produces another 409 and leaves the conflict unresolved. Resolving an already-resolved conflict with a new operation -> 409 conflict_resolved; an identical recorded resolution retry returns its receipt. A changed-content candidate requires use_explicit; no heuristic remapping. GET /position includes all unresolved recording conflicts, with completionCandidate for completion events, so an app restart can recover them. Keep completion resolution commands separate through /completion-conflicts/{id}/resolve with analogous choices and completion base revision. Completion conflict payloads retain the attempted event, capture time and anchor, not just a null audio position.

Completion writes carry an independent baseRevision, layoutRevision, operationId and event. natural_end is emitted only after actual playback reaches the final file's end, with finalPosition anchored at that last file/version/duration. A seek/position update cannot finish a recording. The server validates the terminal anchor and event; it trusts the authenticated client's event rather than claiming cryptographic proof of listening. manual_finish/manual_unfinish use finalPosition=null. Reject invalid event/anchor combinations. A stale completion returns 409 completion_conflict with durable conflictId/currentCompletion and preserves the event. Final file/layout change -> 412. An identical receipt retry is idempotent. Repeated finish events while already finished do not fabricate reread-history entries; manual unfinish preserves previous history. A transition to finished adds one recording completion to the current user's title history without finishing alternative recordings. Explicit unfinish is recorded as a separate event. Separate reread creation/UI is deferred.

## Media and artwork

GET/HEAD /files/{fileId}/versions/{contentVersion}/content always authenticates and checks grants before existence/ETag/Range handling. Return the exact original bytes, fixed content MIME, Content-Length, Accept-Ranges: bytes, strong ETag for that content version, no content transformation/compression and private, no-store. Keep readers and media byte serving outside Huma JSON serialization. HEAD mirrors the status/headers of the same GET request with no body. Evaluate If-Match/If-None-Match normally; a valid matching If-None-Match returns 304, mismatched If-Match returns 412. Mismatched If-Range ignores Range and returns full 200; matching If-Range allows the requested range. Do not redirect media requests or forward secrets across hosts.

Support one bounded/open/suffix byte range with exact 206 Content-Range/Length, including offsets above 4 GiB. Unsatisfiable -> 416 and bytes */size. Malformed syntax -> 400; unsupported multiple ranges are ignored as a whole and return 200. For a suffix larger than the file, return the whole representation as 206; a zero suffix/empty-file range is unsatisfiable. A transient NAS read failure is not a catalog deletion. Credentials are checked at each new request; already-open streams are not promised immediate termination on revocation. After a token expires, the client may refresh/retry a new range; never append a 200 full body to a partial download.

Artwork returns image/* with no redirects, private no-store and accurate length; Auto thumbnails must be <=5 MiB. GET/HEAD share the same permissions and absence behavior. Cast receiver talks only to the preserved phone proxy; upstream server credentials never reach the receiver. Test large-offset and chapter-filter regressions without assuming the Cast SDK/head unit has been physically tested.

## Offline scope and integration boundary

Persist downloads, snapshots, artwork caches, reader/audio progress, restore candidates, pending requests and credential state under stable serverId/userId. Bind every in-flight task to its originating scope and recheck before committing local results; cancellation alone is insufficient. Logout locks the originating scope immediately; switch never reuses old pending operations with new credentials. Preserve locked data/conflicts until an explicit future retention decision. Offline playback has no periodic lease. A network outage is not an authorization denial. Before new online operations validate session/grants; confirmed revoked access stops affected playback/downloads and locks those resources. Restore of a retained scope requires authenticating the same account and rechecking current access.

T003 owns a generated/seeded title + recording + ordered files + grants and real server/Android playback flow. It does not implement general scanning/grouping/managed import, CUE association/parser, annotations/reader sync, full web UI, OPDS/email/KOReader, remote registration/password recovery, reread-history controls, source deletion, production retention or publishing. Unported BookOrbit routes/UI must report unavailable instead of calling an imagined compatible Litara endpoint. Preserve imported player/reader/Cast/Auto code and licensing; do not rewrite media internals to imitate the old API.
